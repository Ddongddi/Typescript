## 1. 카카오톡 및 구형 IMM32 앱 호환성

### 1.1 글자가 한 글자씩 끊겨서 입력되는 현상 (`ㅌpㅅmㅌm`)
카카오톡, 옛 오피스, 메모장(구형), RichEdit 기반 앱은 윈도우의 구형 입력 방식인 **IMM32**를 사용합니다.

#### 기술적 배경:
- 윈도우 운영체제는 현대적인 TSF(Text Services Framework) 입력기의 조합 이벤트를 내부 번역 계층을 거쳐 IMM32 메시지(`WM_IME_COMPOSITION`)로 변환합니다.
- 이때 윈도우는 한국어 입력기에 대해 **"한글 조합은 항상 1음절(Interim)이어야 한다"**는 강제 규칙을 적용합니다.
- 따라서 Typescript처럼 단어 전체(여러 음절)를 밑줄로 미리보기 조합하는 방식은, 한국어 IME로 등록될 경우 글자를 칠 때마다 강제로 앞 글자를 확정해 버려 `테스트`가 `ㅌpㅅmㅌm`으로 깨지는 현상이 발생합니다.

#### 해결책:
- Typescript는 시스템에 **영어(미국) 키보드 레이아웃의 서브 텍스트 서비스**로 등록됩니다.
- 영어 레이아웃에서는 윈도우가 임의로 조합 길이를 제한하지 않으므로, 카카오톡을 비롯한 모든 IMM32 앱에서 여러 음절의 단어 전체가 하나의 매끄러운 조합(Composition)으로 유지됩니다.
- 작업 표시줄에 `ENG`로 표시되는 것은 이 기술적 문제를 해결하기 위한 의도된 동작입니다.

### 1.2 특정 앱에서만 기본 MS 한글 입력기를 쓰고 싶은 경우
만약 특정 사내 보안 프로그램이나 특수 금융 앱에서 Microsoft 기본 한국어 IME가 반드시 필요한 경우, `apps.json`에 다음 규칙을 추가하세요:

```json
{
  "financial_app.exe": {
    "useSystemIme": true
  }
}
```
해당 앱 창으로 전환되면 자동으로 Microsoft 한국어 입력기로 전환되며, 다른 앱으로 벗어나면 다시 Typescript로 복귀합니다.

## 2. 터미널 및 콘솔 환경 최적화

### 2.1 짧은 명령어가 한글로 바뀌는 현상 (`ls` → `ㅣㄴ`)
터미널 환경에서 `ls`, `cd`, `dir`, `git`, `cat` 등의 짧은 알파벳 명령어가 의도치 않게 한글 자모로 판별될 수 있습니다.

#### 해결 방법:
`apps.json`에서 터미널 프로세스의 판별 임계값(`conversionThreshold`)을 상향 조정합니다 (기본값 `0.5` → `0.97`):

```json
{
  "windowsterminal.exe": {
    "conversionThreshold": 0.97
  },
  "powershell.exe": {
    "conversionThreshold": 0.97
  },
  "cmd.exe": {
    "conversionThreshold": 0.97
  }
}
```
임계값을 `0.97`로 설정하면 거의 확실한 한글 타자 패턴이 아닌 한 영문 입력을 최우선으로 유지합니다.

## 3. 에디터(Vim, VSCode) 및 게임 최적화

### 3.1 Vim/VSCode에서 Esc 키가 노멀 모드로 안 넘어갈 때
기본 설정에서 `Esc` 키는 Typescript의 언어 순환(영어 ↔ 한국어) 기능을 수행합니다. 따라서 Vim의 Normal 모드 진입 키와 충돌할 수 있습니다.

#### 해결 방법:
에디터 앱 설정에 `"escapeToApp": true`를 부여합니다:

```json
{
  "code.exe": {
    "escapeToApp": true
  },
  "gvim.exe": {
    "escapeToApp": true
  }
}
```
- 이 설정을 켜면 `Esc` 키가 즉시 에디터로 전달됩니다.
- 언어 순환이 필요할 때는 **`Shift + Esc`**를 누르면 정상적으로 순환됩니다.

### 3.2 게임 실행 시 영문 입력 유지
게임 내 조작키(`W, A, S, D` 등)나 채팅 충돌을 방지하려면 입력을 완전히 패스스루합니다:

```json
{
  "overwatch.exe": {
    "enabled": false
  },
  "steam.exe": {
    "enabled": false
  }
}
```

## 4. 진단 및 디버그 로깅 (`debug.on`)

입력기가 특정 앱에서 비정상적으로 동작하거나 충돌이 의심될 때 이벤트 로그를 수집할 수 있습니다.

### 4.1 로그 활성화
1. `%APPDATA%\Typescript\` 폴더(또는 macOS/Linux 설정 폴더)로 이동합니다.
2. 빈 파일 **`debug.on`**을 생성합니다.
3. 문제가 발생하는 앱을 다시 실행하여 타이핑을 시도합니다.
4. 동일한 폴더에 **`debug.log`** 파일이 생성되어 실시간 TSF 이벤트(포커스 획득/상실, 조합 시작/종료, 캐럿 이동 등)가 기록됩니다.

> 🔒 **개인정보 보호**: 디버그 로그에는 사용자가 타이핑한 텍스트나 키 내용은 일체 기록되지 않으며, 시스템 이벤트 이름과 내부 상태 코드만 남습니다. 확인이 끝나면 `debug.on` 파일을 삭제하세요.

### 4.2 RichEdit 상호작용 검증 도구
리포지토리 소스에서 직접 실제 RichEdit 윈도우를 띄워 TSF/IMM 메시지를 덤프할 수 있습니다:

```powershell
# Typescript 동작 시뮬레이션
cargo run -p typescript-tip --example richedit_lab -- --ts

# Microsoft 기본 IME 동작 비교
cargo run -p typescript-tip --example richedit_lab -- --ms
```

## 5. 자주 묻는 질문 (FAQ)

### Q. 작업 표시줄에 왜 '한'이 아니라 'ENG'로 뜨나요?
**A:** 카카오톡 등 IMM32 기반 앱에서 글자가 한 글자씩 잘리는 Windows 고유의 버그를 우회하기 위해 '영어(미국)' 키보드 아래에 등록되기 때문입니다. 정상적인 동작입니다.

### Q. 단어를 친 직후 Esc를 눌렀는데 이전 단어가 안 바뀌어요.
**A:** 확정 직후 되돌리기(Undo/Flip)는 애플리케이션이 캐럿 앞의 텍스트를 읽을 수 있도록 허용하는 환경(TSF를 완벽히 지원하는 모던 앱)에서만 가능합니다. 텍스트 읽기 권한을 주지 않는 터미널이나 보호된 입력창에서는 확정 후 Esc가 앱으로 직접 전달됩니다.

### Q. 한/영 키로 단어 언어 전환이나 일시정지(Alt+한/영)가 동작하지 않아요.
**A:** 노트북이나 특수 키보드에서 한/영 키가 오른쪽 Alt(`VK_RMENU`)로 매핑되어 있는 경우가 있습니다. 대시보드 설정의 "키 지정"에서 `＋ 키 추가`를 누르고 실제로 쓰는 키를 눌러 지정하세요. macOS에서는 **Option + Space**, Linux에서는 **한/영(Hangul)** 또는 **Pause** 키를 사용합니다.
