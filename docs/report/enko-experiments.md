# 한·영 판별 실험 — 2026-10-19

채택한 변경은 **검증 분할 누수 수정**과 **기존 점수를 보존하는 할당 제거**다.
단어 예외·조사 목록·판별 임계값은 추가하거나 조정하지 않았다.
학습 모델 두 가지는 기존 엔진보다 전체 품질이 낮아 제품에 적용하지 않았다.

## 비교 조건

- 변경 전: `1560114`의 release lab 실행 파일을 보관해 비교.
- Windows x64, Intel Core Ultra 7 155H, Rust 1.93.1. 제품과 같은 release 설정.
- 개발 평가: `--profile enko --fold 0/3 --corpus 3000 --misses 3 --steady`.
- 마지막 기본 엔진 검증: 같은 옵션의 `--fold 2/3`. 모델 선택에 사용하지 않았다.
- 빌드·테스트·학습과 지연 측정은 겹치지 않게 실행했다.
- 출력의 과거 baseline 열 대신 이번에 다시 실행한 변경 전/후의 `now` 열을 비교했다.
  기존 baseline 파일과 golden 정답은 갱신하지 않았다.

`acc.ALL`은 공통 평가 정확도이며 `big.*` 문장 정확도를 포함하는 전체 코퍼스 평균은 아니다.
아래 표는 이 지표를 다른 종류의 정확도와 구분한다.

## 1. 원형 단어별 검증 분할

기존 튜너는 행 번호 `% 5`로 나누어 같은 원형의 변형이 학습·검증 양쪽에 들어갔다.
원형의 대소문자를 정규화한 안정적 해시로 분할하여, 조사 결합·다른 한국어 단어 결합·
원형 단독을 같은 쪽에 배정했다. `--audit-tune` 결과:

| 항목 | 학습 | 검증 | 겹침 |
| --- | ---: | ---: | ---: |
| 원형 그룹 | 28,640 | 7,085 | 0 |
| 전문 용어 원형 | 160 | 49 | 0 |
| 전문 용어+어미 사례 | 1,280 | 392 | 원형 기준 0 |
| 전문 용어+단어 사례 | 480 | 147 | 원형 기준 0 |

전체 세트에서 동일 키열의 학습/검증 겹침도 0건이다. 일반 lab은 분할 변경 전후
정확도·시나리오·미리보기 관련 지표 121개가 동일했다. 튜너의 이전 검증 점수와는
비교할 수 없다. 이 작업에서는 기존 휴리스틱 가중치의 재튜닝을 실행하지 않았다.

이 감사는 구성한 평가 사례의 원형과 키열에 대한 것이다. 기존 사전의 어휘나 웹 문서의
출처까지 학습에서 제외했다는 뜻은 아니다.

## 2. 규칙을 추가하지 않는 학습 모델

가장 작은 초기 실험으로 raw 키 n-gram과 언어 전이 점수만 학습하는 **linear-chain CRF**를
lab에 구현했다. segmental CRF는 아직 구현하지 않았다. 사전·조사·단위 목록이나 수작업
점수는 사용하지 않는다. 한국어로 입력할 수 없는 키를 제외하는 물리적 자판 제약만 둔다.

- 입력당 각 키의 영어/한국어 태그를 예측하고, 연속 한국어 구간을 기존 조합기로 출력.
- 키 1~3-gram, 위치 ±2의 국소 문맥, 이전 언어, 처음/끝 특징을 해시한 32,776개 가중치.
  미리보기에서는 그 시점까지 입력된 키만 보인다.
- 영어 문장·한국어 문장·댓글의 행 fold `1/3`에서 추출. 내부 검증은 단어 그룹 해시의
  별도 fold. 학습 12,281개, 내부 검증 1,985개, AdaGrad 6 epoch 고정.
- 혼합어 4,000개는 학습 쪽 영어/한국어 단어로 합성. 첫 실험은 전체 단어를 연결한다.
- 두 번째 실험은 한국어 부분을 Unicode 문자 경계에서 잘라 연결한다. 잘린 조각도
  학습 분할에 속하는 경우만 사용하고, 같은 수의 혼합어를 채운다.
- 학습 코드는 독립 lab에만 존재한다. 모델 파일 약 256KiB는 커밋하거나 제품에 넣지 않는다.

| 개발 평가 (%) | 기존 엔진 | 전체 단어 연결 CRF | 조각 연결 CRF |
| --- | ---: | ---: | ---: |
| 공통 `acc.ALL` | 99.69 | 98.14 | 97.98 |
| 짧은 혼합어 문장 `big.cs_short.bare.sentence` | 64.70 | **76.04** | 65.97 |
| 혼합어 조사 문장 `big.cs.particle.sentence` | 99.06 | 58.48 | 65.61 |
| 별도 용어 조사 문장 `big.cs_heldout.particle.sentence` | 98.95 | 62.81 | 70.99 |
| 영어 문장 `big.en.sent.sentence` | 99.93 | 97.90 | 91.50 |
| 한국어 문장 `big.ko.sent.sentence` | 99.13 | 91.57 | 94.87 |
| 채팅 속어 `sc.chat.slang` | 88.24 | 17.65 | 64.71 |
| 내부 검증 단어 | 99.798 | 99.395 | 99.144 |

**두 모델 모두 기각.** 첫 모델은 짧은 혼합어에서 가능성을 보였지만, 일반 문장과 조사
경계의 손실이 훨씬 크다. 조각 합성만으로 해결되지 않았다. 내부 단어 정확도나 학습
손실 감소만으로 채택할 수 없다는 결과다. 규칙을 덧붙이거나 정답 사례를 학습에 넣어
수치를 보완하지 않았다.

이 모델의 confidence는 최적 태그 경로의 조건부 확률이다. 출력 문자열의 정답 확률로
보정하지 않았으며 제품 자동 확정 기준으로 쓰면 안 된다. 행별 분할은 문서와 어휘의
완전한 독립성을 보장하지 않는다. 조각 실험은 첫 결과를 보고 선택한 개발 실험으로,
새로운 독립 검증의 성공으로 해석하지 않는다.

## 3. 점수 보존 최적화

ASCII 입력의 영어 점수 계산에서 문자 필터 String, 소문자 String, 인코딩 Vec 생성을
제거했다. 이미 있던 스트리밍 trigram 합을 재사용하며, 합산 순서와 분모를 유지한다.
비 ASCII 입력은 기존 경로를 유지한다. 비어 있는 입력을 포함한 경계 사례와 모든
소문자 두 글자 조합에서 기존 수식과 `f64` 비트가 같은지 검사한다.

코퍼스를 제외한 같은 lab을 순서를 번갈아 7쌍 실행했다:
`--profile enko --no-corpus --steady --misses 0`.
각 실행의 평균 지연을 수집하고, 7개 평균의 중앙값을 비교했다.

| 지표 (μs) | 변경 전 중앙값 | 변경 후 중앙값 |
| --- | ---: | ---: |
| 확정 `commit.avg_us` | 6.32 | 5.90 |
| 키 입력 `keystroke.avg_us` | 5.79 | 5.35 |
| 키 입력 p95 | 11.50 | 11.00 |
| 키 입력 p99 | 27.30 | 26.00 |

| 쌍 | 순서 | 전: 키 입력 평균 (μs) | 후: 키 입력 평균 (μs) |
| --- | --- | ---: | ---: |
| 1 | 전→후 | 16.41 | 12.02 |
| 2 | 후→전 | 15.88 | 13.82 |
| 3 | 전→후 | 6.48 | 5.35 |
| 4 | 후→전 | 5.79 | 5.26 |
| 5 | 전→후 | 5.20 | 5.23 |
| 6 | 후→전 | 5.22 | 5.03 |
| 7 | 전→후 | 5.25 | 6.57 |

키 입력 평균의 중앙값은 약 7.6% 낮았지만, 기계 부하·워밍업 편차가 커서 보장된
속도 향상률로 주장하지 않는다. 메모리 loaded/peak 지표는 동일했다. 채택 근거는
중간 할당을 없애면서 계산 결과가 같고 lab 정확도 회귀가 없다는 점이다.

개발 fold의 관련 지표 121개와 최종 fold `2/3`의 같은 지표 모두 변경 전후 동일하다.
최종 fold 예: 공통 99.69%, 짧은 혼합어 문장 65.13%, 영어 문장 99.93%, 한국어 문장 99.03%.
실제 OS에서 화면이 갱신되기까지의 지연을 측정한 것은 아니다.

## 검증

통과: workspace 기본/전체 기능 테스트(기존 golden 포함), 양쪽 구성의 전체 target
Clippy, lab 테스트 7개와 Clippy, workspace/lab rustfmt, 설치 언어 격리 검사 11개.
첫 CRF 모델은 최종 학습 코드로 재생성한 파일과 바이트 단위로 동일하다.
macOS·Linux·Android의 네이티브 실행과 실제 IME 화면 반영 시간은 검사하지 않았다.
