# 릴리즈 점수 규격 v2

[`performance.md`](performance.md)의 측정값으로 릴리즈 하나의 총점을 계산하는 규격입니다. 계산기는 [`lab/score.py`](../../lab/score.py)이고, 결과 그래프는 `performance.md` 맨 위에 있습니다. 기준일 2026-10-16.

## 1. 한눈에

점수는 10000점 만점이고 높을수록 좋습니다. 정확도·용량·속도·메모리를 하나의 숫자로 합칩니다. 영어·한국어(영-한) 기준이며 일본어는 포함하지 않습니다([일본어 개선 보고서](japanese-improvement.md)에서 별도).

```
Score = 10000 × exp( − L환율 − L예산 − L회귀 )
```

- **L환율**: 지표마다 '목표보다 몇 배 나쁜가'를 로그로 재서 계수를 곱해 더합니다. 정확도와 용량의 계수가 크고 속도와 메모리는 작습니다.
- **L예산**: 절대 한도를 넘는 지표가 있으면 제곱으로 감점합니다.
- **L회귀**: 기준 릴리즈보다 허용치 이상 나빠진 지표가 있으면 제곱으로 감점합니다.

세 항은 모두 0 이상이라 감점이 없으면 10000점입니다. 필요한 함수는 `ln`과 `exp`뿐이라 스프레드시트로도 계산됩니다.

## 2. 계산 순서

1. `performance.md`에서 릴리즈 값을 3절의 키로 옮겨 적습니다.
2. 4절 표로 L환율을 계산합니다.
3. 5절 표로 L예산을 계산합니다.
4. 기준 릴리즈가 있으면 6절로 L회귀를 계산합니다. 없으면 0입니다.
5. `Score = 10000 × exp(−(L환율 + L예산 + L회귀))`.

`lab/score.py`는 이 순서를 그대로 구현한 것입니다.

```sh
python lab/score.py metrics.json   # {"v0.8.7": {"acc.ALL": 99.78, ...}, ...} 릴리즈 순서대로
```

각 릴리즈는 바로 앞 릴리즈를 기준으로 L회귀를 계산하고, 줄마다 `태그  L환율  L예산  L회귀  점수`를 찍습니다.

## 3. 입력값 만드는 법

- **정확도 세트**: `x = 100 − 정확도(%)`, 즉 오류율입니다.
- **시나리오**: 유형별 시나리오 표 '전체' 행의 '문장' 값을 씁니다(token 값이 아닙니다). lab 출력 키로는 `sc.ALL.sentence`이고, 점수 키로는 `scenario.all.sentence`입니다.
- **속도**: 속도·메모리 표의 µs 값을 그대로 씁니다.
- **용량**: 크기 표의 KiB 값을 그대로 쓰고, `size.packs`만 en 팩과 ko 팩의 합입니다.
- **메모리·시작**: `heap.peak_kb`, `heap.loaded_kb`, `load.ms`를 그대로 씁니다.

모든 값은 그 릴리즈 자기 절(`## 0.8.7` 같은 절)의 값을 씁니다. 맨 위 '한눈에' 표의 '개선 후' 값이나 중간 측정값은 쓰지 않습니다.

## 5. L예산

```
L예산 = Σ ln( max(1, x / B) )²
```

한도 `B` 이하는 0이고, 넘으면 제곱으로 커집니다. 1.2배 초과는 점수 −3%, 2배는 −38%, 3배는 −70%입니다. 오류율 지표는 `x = 100 − 정확도`이고, 측정되지 않은 세트의 예산은 건너뜁니다.

## 6. L회귀

기준 릴리즈(기본은 직전 릴리즈)보다 허용치 `τ`를 넘어 나빠진 만큼만 제곱으로 감점합니다.

```
z = max(0, ln(x ÷ x기준) − ln(1+τ)) ÷ σ        (속도·용량·메모리)
z = max(0, (정확도기준 − 정확도) − 0.05) ÷ 0.5   (정확도, %p 단위)

L회귀 = 1.5 × [ W정확도·mean(z²) + W용량·mean(z²) + W속도·mean(z²) + W메모리·mean(z²) ]
```

| 영역 | W | 대상 지표 | 허용 τ | 1단위 σ |
| --- | ---: | --- | --- | --- |
| 정확도 | 0.4255 | `acc.ALL`, `big.ko.sent.sentence`, `big.en.sent.sentence`, `big.cs.particle.sentence`, `big.cs_heldout.particle.sentence`, `scenario.all.sentence` 중 기준과 이번 릴리즈 모두 측정된 것 | 0.05%p | 0.5%p |
| 용량 | 0.4043 | `size.zip`, `size.x64`, `size.x86`, `size.packs` (평균은 4개) | 2% | ln 1.5 |
| 속도 | 0.0851 | `keystroke.p95_us`, `keystroke.p99_us`, `commit.p95_us`, `commit.p99_us` (평균은 4개) | 25% | ln 2 |
| 메모리·시작 | 0.0851 | `load.ms` (τ 25%), `heap.loaded_kb`, `heap.peak_kb` (τ 5%) (평균은 3개) | 위와 같음 | ln 2 |

`W`는 영역 지수를 합 1로 맞춘 값(`a ÷ 0.94`)입니다. 의도적으로 교환한 변화(예: load 지연을 감수하고 heap을 줄임)는 기준 릴리즈를 재고정하고 사유를 남깁니다. 기준 값이 0인 지표(예: 팩이 없던 시절의 `size.packs`)는 나빠질 수 없으므로 z = 0입니다.

## 7. 점수 읽는 법

- **교환 한계**: 오류율을 절반으로 줄이면 용량은 +21%까지, 30% 줄이면 +15%까지, 15% 줄이면 +9%까지 늘어도 점수가 오릅니다.
- **지표 하나만 바뀔 때**(0.8.7 기준): 오류율 절반 +22%, 용량 ×1.1 −6%, 용량 ×1.3 −31%, 용량 ×0.8 +9%.
- **잡음**: 같은 컴퓨터에서도 지연이 10~20% 흔들리므로, 점수 ±2%(약 ±70점) 이내의 차이는 같은 값으로 봅니다.


## 9. 운영 규칙

1. 이 규격을 '점수 v2'로 고정합니다. 세트나 항목을 추가하면 v3로 올리고, 과거 릴리즈는 원자료로 재계산합니다. 0.8.7에 새로 생긴 `big.ko.phrase.sentence`, `big.ko.long.sentence`는 v3 후보입니다.
2. 릴리즈 시점 측정값만 씁니다.
3. 릴리즈끼리 비교할 때는 둘 다에 있는 세트만으로 계산한 점수를 씁니다. 새 세트는 더 어려워서 전체 점수가 낮게 나옵니다. 위 예시에서 0.8.7은 공통 세트로 3977, 전체 세트로 3625입니다.
4. 예산은 그 릴리즈에서 실제 측정된 세트에만 적용합니다.
5. 점수 ±2% 이내의 차이는 잡음으로 봅니다.
6. 일본어 등 새 언어 모듈을 넣으면 그 언어의 정확도 세트와 팩 용량을 새 항목으로 추가하고 규격 버전을 올립니다.

## 10. 과거 릴리즈를 한꺼번에 채점하는 법 (그래프용)

`performance.md` 맨 위 그래프는 위 예시와 입력이 다릅니다. 릴리즈마다 절이 없는 옛 버전까지 같은 잣대로 비교하려고 이렇게 잽니다.

1. 현재 커밋의 `lab`에 그 태그의 `crates/core`(와 `crates/packgen`)만 갈아 끼운 worktree를 만들고, `lab/data`는 **복사**해 둡니다(링크로 연결한 worktree를 `--force`로 지우면 실제 데이터가 지워집니다).
2. held-out 용어 목록은 태그가 아니라 **현재 `packgen`** 으로 고정합니다. 태그마다 목록이 다르면 세트가 달라져 비교가 깨집니다.
3. 팩 구조 이전(0.3.0 이하)은 `make_engine` 호출 모양만 맞춰 같은 lab에 붙이고, `size.packs`는 0으로 둡니다. 코어에 없는 API를 쓰는 `lab/src/tune.rs`는 그 worktree에서만 뺍니다.
4. 모든 태그의 lab 바이너리를 만든 뒤, 한 바퀴에 태그마다 한 번씩 번갈아 5바퀴 돌려 지표별 중앙값을 냅니다(기계 상태의 흔들림이 모든 태그에 같이 걸립니다).
5. 크기는 릴리즈 절이 없는 옛 버전도 있으므로 모든 릴리즈에서 GitHub 릴리즈 에셋을 씁니다. `size.zip`은 `tacit-windows.zip`, `size.x64`와 `size.x86`은 그 zip 안의 `tacit_tip.dll`과 `tacit_tip_x86.dll`, `size.packs`는 팩 에셋(en + ko)의 합입니다. CI 빌드라 로컬 빌드보다 약 3% 큽니다.
6. 위 값을 `metrics.json`(`{태그: {지표: 값}}`, 릴리즈 순서)에 담아 `python lab/score.py`에 넘깁니다.

이렇게 계산한 점수는 8절의 예시(릴리즈 절의 값)와 달라서, 그래프의 0.8.7(3871)과 예시의 3625는 서로 다른 입력의 결과입니다.

## 11. 영역별 점수

`performance.md`의 '모든 릴리즈' 표에는 총점 옆에 정확도·용량·속도·메모리 점수가 있습니다. 4절의 지표별 항 `계수 × ln(max(x, T) ÷ T)`를 영역(정확도 세트, `size.*`, `keystroke.*`·`commit.*`, `heap.*`·`load.ms`)별로 모은 합을 그 영역의 계수 합(정확도 0.40, 용량 0.38, 속도 0.08, 메모리 0.08)으로 나눈 값이 영역의 평균 로그비 r입니다.

```
영역 점수 = 10000 × exp(−r)
```

영역의 모든 지표가 목표에 닿으면 10000점이고, 목표보다 평균 2배 나쁘면 5000점입니다. 총점의 L환율은 `0.40·r정확도 + 0.38·r용량 + 0.08·r속도 + 0.08·r메모리`라서 총점은 네 영역 점수의 평균이 아니며, 영역 점수에는 L예산과 L회귀가 들어가지 않습니다. 계산은 `lab/score.py`의 `areas()`입니다.
